오늘은 그 과정을 처음 해 보시는 분도 따라 하실 수 있게, 용어부터 차근차근, 제가 막혔던 곳까지 솔직하게 보여 드릴게요.

Claude Code는 그냥 대화만 하는 Claude가 아니라, 제 컴퓨터에 파일을 직접 만들고 고칠 수 있는 Claude예요. 저는 Claude 데스크톱 앱의 Code 탭에서 썼습니다.

스킬은 쉽게 말해 작업 설명서예요. 예를 들어 "발표자료는 이런 순서로, 이런 디자인 규칙으로 만들어라" 하는 설명서를 설치해 두면, Claude가 발표자료 일을 할 때 그걸 꺼내 읽고 따라 합니다. 플러그인은 그런 스킬과 도구 여러 개를 묶은 꾸러미고요.

HTML 슬라이드는 파워포인트 파일이 아니라 웹 페이지로 만든 발표자료예요. 그리고 GitHub는 파일을 인터넷에 보관하는 곳, GitHub Pages는 거기 올린 파일을 무료 웹사이트로 열어 주는 기능입니다. 이 정도만 아시면 충분해요.

왜 HTML일까요?

파워포인트 대신 웹 페이지로 만든 이유

비교파워포인트 파일HTML 슬라이드
여는 방법프로그램이 깔려 있어야 함브라우저만 있으면 됨 (PC·태블릿·휴대폰)
나눠 주기파일을 메일·메신저로 전송인터넷 주소 하나로 공유
발표 대본메모 칸에 따로 작성장마다 대본 내장, S 키로 발표자 창
디자인 바꾸기장마다 손으로 수정테마 파일 하나만 바꾸면 전체가 바뀜
AI와 함께 작업파일 구조가 복잡함글자로 된 파일이라 Claude가 읽고 고치기 쉬움

그럼 왜 굳이 파워포인트가 아니라 HTML로 만들었을까요?

가장 큰 이유는 여는 방법이에요. 파워포인트는 프로그램이 있어야 하지만, HTML 슬라이드는 브라우저만 있으면 학교 컴퓨터든 태블릿이든 휴대폰이든 열립니다. 나눠 줄 때도 파일을 보내는 게 아니라 주소 하나만 알려 주면 돼요.

두 번째는 발표 대본이에요. 장마다 대본이 숨어 있다가 S 키를 누르면 발표자 창에 나옵니다. 뒤에서 화면으로 보여 드릴게요.

세 번째, AI와 일하기에 좋아요. HTML은 글자로 된 파일이라서 Claude가 읽고 정확하게 고칠 수 있거든요. "3번 장 글자를 키워 줘"라고 하면 딱 그 부분만 고쳐 줍니다.

그러자 Claude가 영상 자막을 읽어서 무슨 도구가 필요한지 파악했고, 인터넷에서 그 스킬을 찾아 코드를 먼저 읽어 봤어요. 그리고 남이 만든 코드를 설치하는 거라서 "설치해도 될까요?" 하고 저한테 확인을 받았습니다. 이 확인 절차가 있어서 안심이 됐어요.

중간에 다른 분이 소개한 GitHub 주소도 하나 보여 주면서 "이것도 설치하면 좋을까?" 물었더니, 장단점을 비교해 주더라고요. 좋다고 해서 그것도 설치했습니다.

포인트는, "좋은지 먼저 검토해 줘"라고 물어볼 수 있다는 거예요. 무작정 설치하지 않아도 됩니다.

html-ppt 스킬 안을 들여다보면 재료가 정말 많아요.

테마가 36종이에요. 테마는 발표자료가 입는 옷이라고 생각하시면 돼요. 색, 글꼴, 분위기가 한 번에 바뀝니다. 레이아웃은 31종인데 표지, 표, 연대표, 차트 같은 페이지 틀이고요. 글자가 아래에서 떠오르는 효과나 별이 움직이는 배경 같은 애니메이션도 마흔일곱 가지가 있어요.

이게 왜 중요하냐면, Claude가 빈 종이에서 시작하지 않기 때문이에요. 이미 잘 만들어진 틀을 골라서 내용만 갈아 끼우니까, 처음 만든 발표자료도 디자인이 깔끔하게 나옵니다.

스킬 설명서에도 "항상 견본에서 시작하라"고 적혀 있어요. 사람이 일할 때와 똑같죠.

커밋 · 푸시

이 순서는 Claude가 기억해 두기 때문에, 저는 매번 설명하지 않아요.

첫 번째 발표자료를 올리고 나니, 두 번째부터는 정말 간단해졌어요. "이전처럼 깃허브에 올려 줘" 한마디면 됩니다.

뒤에서는 세 단계가 돌아가요. 첫째, 발표자료마다 폴더 하나에 넣어요. 테마나 스크립트 같은 공용 파일은 모든 발표자료가 함께 써서 용량도 아끼고요.

둘째, 목록 파일에 한 줄을 적어요. 제목, 소개, 주제, 날짜예요. 그리고 스크립트를 한 번 돌리면 표지 그림, 전체 목록, 장수 세기까지 자동으로 됩니다. 사람이 목록을 손으로 고치다가 틀릴 일이 없죠.

셋째, 바뀐 걸 기록하고 올려요. 이걸 커밋과 푸시라고 해요. 이 순서를 Claude가 기억해 두기 때문에, 새 대화에서도 제가 다시 설명할 필요가 없어요.

점검design-taste-frontend 스킬

  • “taste 스킬 기준으로 다듬어 줄 수 있나요?”
  • 첫 측정: FAIL 5개, 경고 6개 → 고친 뒤 FAIL 0개
  • “객관적으로 평가해 보고 개선할 점을 알려 주세요”
  • 발표자료가 40편이라고 가정한 시험 페이지로 미리 점검

개선쌓여도 찾기 쉽게

  • 검색창과 주제 버튼(철학·문학·심리·AI·투자)
  • 학기별로 묶어 보기
  • 발표자료에서 목록으로 돌아가는 링크
  • 카카오톡에 주소를 붙이면 뜨는 공유 그림

마지막 다섯 번째 단계는 다듬기예요. 발표자료가 쌓이니까 모아 둔 사이트도 보기 좋게 만들고 싶어졌어요.

여기서는 design-taste-frontend라는 디자인 점검 스킬을 썼어요. "taste 스킬 기준으로 다듬어 줄 수 있나요?"라고 했더니, 사이트를 측정해서 문제 다섯 개를 찾고 모두 고쳤어요.

제가 좋았던 질문은 이거예요. "올리기 전에 네 스스로 객관적으로 평가해 보고 개선할 점을 알려 주세요." 그러자 발표자료가 마흔 편이라고 가정한 시험 페이지를 만들어서, 쌓였을 때 어떤 문제가 생길지 미리 보여 줬어요. 휴대폰에서 목록이 열 화면 가까이 이어진다든지 하는 것들이요.

그래서 검색창과 주제 버튼, 학기별 묶음, 돌아가는 링크, 카카오톡 공유 그림까지 넣었어요. 미래를 가정해서 점검해 달라는 부탁, 꼭 한번 해 보세요.

사이트에 제 브랜드도 입혔어요. 유튜브 프로필로 만든 원고지 칸 '정' 로고가 있는데, 그 이미지를 주면서 "이걸 바탕으로 브랜드를 만들어 달라"고 했더니 종이색, 먹색, 주홍색 세 가지로 사이트 전체를 바꿔 줬어요.

그리고 일을 편하게 만든 도구가 세 가지 있어요. 첫째 별도 세션. 긴 작업을 다른 대화창에 맡겨서 동시에 진행하는 거예요. 찰리 멍거 발표자료는 제가 다른 일을 하는 동안 옆 창에서 만들어졌어요.

둘째 기억. 한 번은 Claude가 갑자기 영어로 답해서 "앞으로 한국어로만 답해 달라"고 했는데, 그걸 기억해 둬서 다음 대화부터는 그런 일이 없어요. 셋째 이어가기. 대화가 너무 길어지면 지금까지 한 일을 메모로 남기고 새 대화에서 이어서 해요.

처음부터 다 쓰실 필요는 없어요. 익숙해지면 하나씩 써 보세요.
